# Project instructions

1. For every shadcn component or block request, use both the shadcn skill and the shadcn MCP.
2. Write all README content, project notes, and related documentation in English.

3. Before planning or changing Amautai, read the current product document and relevant comments: https://docs.google.com/document/d/16DhBCPXhS6Wyuar9op7BviHpD2T06TSzRprB9iZlWjg/edit. If access fails, report it; flag conflicts with user instructions or code before dependent changes.
4. Keep the shared product Google Doc in Spanish; this is an exception to rule 2.
5. For Amautai backend changes or reviews, read and apply [.agents/skills/amautai-backend/SKILL.md](.agents/skills/amautai-backend/SKILL.md).
6. For Amautai frontend changes or reviews, read and apply [.agents/skills/amautai-frontend/SKILL.md](.agents/skills/amautai-frontend/SKILL.md).
7. Before planning or implementing Amautai features, read [docs/HACKATHON_RUBRIC.md](docs/HACKATHON_RUBRIC.md) and consult its preserved source PDF for scoring or eligibility details.
8. Keep native fetch and architecture boundaries enforced; run pnpm run check after architecture changes, and preserve the dependency gate in root lint and build.
9. For survey links, question scope, and pitch evidence, read [docs/PROBLEM_VALIDATION_SURVEYS.md](docs/PROBLEM_VALIDATION_SURVEYS.md).

10. For UI design changes, read and apply [.agents/skills/shadcn-design/SKILL.md](.agents/skills/shadcn-design/SKILL.md).
11. After every documentation change, update the shared product Google Doc in Spanish with that change: https://docs.google.com/document/d/16DhBCPXhS6Wyuar9op7BviHpD2T06TSzRprB9iZlWjg/edit.

# Project instructions

1. For every shadcn component or block request, use both the shadcn skill and the shadcn MCP.
2. Write all README content, project notes, and related documentation in English.

3. For Amautai backend changes or reviews, read and apply [.agents/skills/amautai-backend/SKILL.md](.agents/skills/amautai-backend/SKILL.md).
4. For Amautai frontend changes or reviews, read and apply [.agents/skills/amautai-frontend/SKILL.md](.agents/skills/amautai-frontend/SKILL.md).
5. Before planning or implementing Amautai features, read [docs/HACKATHON_RUBRIC.md](docs/HACKATHON_RUBRIC.md) and consult its preserved source PDF for scoring or eligibility details.
6. Keep native fetch and architecture boundaries enforced; run pnpm run check after architecture changes, and preserve the dependency gate in root lint and build.
7. For survey links, question scope, and pitch evidence, read [docs/PROBLEM_VALIDATION_SURVEYS.md](docs/PROBLEM_VALIDATION_SURVEYS.md).

8. For UI design changes, read and apply [.agents/skills/shadcn-design/SKILL.md](.agents/skills/shadcn-design/SKILL.md).
9. Localize all new or changed UI copy, errors, validation, loading states, formats, and accessibility labels in Spanish, Chanka Quechua, and Peruvian Aymara; verify all three locales without layout regressions and preserve user-authored content and original sources.
10. For UI animation changes, read and apply [.agents/skills/motion-design/SKILL.md](.agents/skills/motion-design/SKILL.md).
